# 사후 기록 (postmortems)

고장 하나를 잡을 때마다, 다시 만났을 때 30초 만에 알아볼 수 있을 만큼만 적어 둔다.

`docs/` 의 번호 붙은 문서들이 "이 저장소가 어떻게 생겼는가"를 설명한다면, 여기는
**"무엇이 어떻게 조용히 망가졌는가"** 를 모은다. 둘을 나눈 이유는 성격이 달라서다.
구조 설명은 한 번 쓰면 오래 가지만, 고장은 날짜와 버전에 묶여 있고 대개
"그때 그 조합에서만" 성립한다.

## 무엇을 여기 적나

여기 들어올 자격은 **에러 메시지 하나로 안 끝난 것** 이다. 로그에 빨간 줄이 뜨고
그 줄을 검색해서 고쳤다면 적을 게 없다. 반대로 이런 것들은 적는다:

- 에러가 아예 안 났는데 기능이 없다 (제일 비싼 종류)
- 성공했다고 보고하는데 화면은 그대로다
- 증상과 원인이 다른 층에 있다 (설정을 고쳤는데 원인은 systemd 였다든지)
- 진단하려고 쓴 도구가 증상을 만들었다

## 쓰는 법

파일 하나 = 한 번의 조사. 이름은 `YYYY-MM-DD-주제.md`.

각 건은 **증상 → 원인 → 고침 → 다음에 빨리 잡는 법** 순으로 적는다. 마지막 항목이
제일 중요하다 — 미래의 나는 원인 설명이 아니라 "무슨 명령을 치면 보이나"를 찾으러
온다.
