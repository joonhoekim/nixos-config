# nixos-config 학습 문서

이 저장소(dustinlyons/nixos-config 기반, macOS/nix-darwin 중심)를 이해하고 운영하기 위해
정리한 학습 노트 모음입니다.

Nix의 동작 원리, 이 저장소의 구조, flake, macOS 설정 관리의 범위와 한계,
최초 셋업에서 겪는 함정, 자주 쓰는 명령어 등을 다룹니다.

## 보는 법

이 디렉토리(`docs/`)의 문서들을 직접 살펴보세요. 파일 이름 앞 번호는 대략적인 읽기 순서입니다.
`research/`에는 자유 형식의 분석 글이, `archive/`에는 세 편으로 압축되기 전의 원본 문서가 들어 있습니다.

[`keymap.md`](keymap.md)는 학습 노트가 아니라 **정본**입니다 — 하이프랜드·니리·rift가
공유하는 키 배치를 한 곳에 모았습니다. 세 설정 파일은 이걸 각자의 문법으로 옮긴
것이고, 배치를 바꾸려면 여기부터 고쳐야 합니다. 세 창 관리자를 오가며 쓰기 때문에
근육기억이 갈리는 것이 가장 큰 비용이고, 정본이 둘이 되면 반드시 한쪽만 낡습니다.

[`hyprland-binds.md`](hyprland-binds.md)는 그 아래층입니다 — 배치가 아니라
**하이프랜드에서 무엇을 부를 수 있는가**입니다. 쓸 수 있는 디스패처·레이아웃 메시지
목록을 돌고 있는 컴포지터에서 직접 뽑아 적었고, 조용히 실패하는 함정들을 함께
담았습니다.

[`clean-install.md`](clean-install.md)는 **절차서**입니다 — 빈 기기에 이 설정을 얹어
부팅시키기까지, Secure Boot를 끄는 데서 시작해 첫 로그인에서 끝납니다. 학습 노트가
아니라 순서대로 따라 치는 문서이고, 그래서 왜 그런지보다 **어디서 깨지는지**를 더
많이 적었습니다(git이 추적하지 않는 `hardware-configuration.nix`, 재귀하지 않는
`createHome`의 chown 같은 것들). 레포 쪽 규칙은 루트 [README](../README.md)가 이어받습니다.

[`browser-tooling.md`](browser-tooling.md)는 **도구 안내서**입니다 — 로컬 웹 앱을 눈으로
확인해야 할 때 쓰는 브라우저 자동화·스크린샷·이미지 비교 도구가 무엇이 깔려 있고 어떻게
쓰는지, 그리고 무엇을 일부러 안 넣었는지를 적었습니다. 선언만 해 두고 문서를 안 남기면
깔려 있다는 사실 자체를 잊어버리기 때문에 짝으로 둡니다.

[`local-inference.md`](local-inference.md)는 **운영 기록**입니다 — evo-t1에서 로컬 모델을
돌리는 구성 전체를, 디스크를 세우는 것부터 iGPU 추론 속도를 실측하는 것까지 한 번에
적었습니다. `/mnt/ai` 파일시스템만 선언적이고 그 위의 LM Studio 구성은 전부 명령형이라,
클린 설치 후에는 이 문서가 유일한 재현 수단입니다. 성능 수치는 GPU 대 CPU 배수와 함께
**그 배수를 곧이곧대로 읽으면 안 되는 이유**도 같이 적었습니다. 표를 만든
[`bench-inference.py`](bench-inference.py)를 옆에 같이 둡니다 — 하드웨어나 런타임이
바뀌면 다시 돌려야 하는 수치들이고, 스크립트가 없으면 같은 방법으로 다시 재는 것부터
추측이 됩니다.

[`appimage-on-nixos.md`](appimage-on-nixos.md)는 **구조 설명**입니다 — AppImage가 왜 NixOS에서만
그냥 실행되지 않는지, `appimage-run`이 마운트 대신 무엇을 하는지, 그리고 앱이 만드는 파일이
어느 계층에 생기는지를 적었습니다. 핵심은 세 계층(불변인 AppImage / 일회용 추출 캐시 /
사용자 데이터)을 구분하는 것입니다 — 고칠 일이 생겼을 때 어디를 건드려야 하는지가 직관과
다르고, 잘못된 층을 고치면 다음 업데이트에서 조용히 사라집니다.

[`postmortems/`](postmortems/)는 성격이 다릅니다 — 구조 설명이 아니라, 실제로 겪은 고장의
기록입니다. **에러 메시지 없이 조용히 실패한 것들**만 모읍니다("고쳤는데 화면이 안 바뀐다",
"유닛은 enabled인데 안 뜬다"). 같은 증상을 다시 만났을 때 무슨 명령을 쳐야 보이는지가 핵심입니다.

## 한 줄 요약

설정을 "데이터"로 빌드해 `/nix/store`에 박제하고, 라이브 시스템이 그 데이터에 수렴하도록 "활성화"한다.
패키지든 `/etc`든 dock이든 전부 같은 원리. macOS에서는 Apple이 스크립트로 열어둔 표면까지만 닿을 수 있다.
