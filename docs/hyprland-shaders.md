# 하이프랜드 화면 셰이더 — 파일별 설계 메모

`modules/nixos/hyprland/rice/shaders/<갈래>/<이름>.frag` 는 하이프랜드의 `decoration:screen_shader` 로 거는 GLSL
프래그먼트 셰이더다. 컴포지터가 렌더링을 끝낸 화면 한 장(`tex`)을 받아 한 장을 내놓는다.

공통 규약 — 유니폼 표, 체인, 탭 곱, vfr/damage 두 축, `!motion`, `// @범위` 손잡이, 머리말 첫 줄 blurb — 은
`modules/nixos/hyprland/rice/README.md` 에 있다. 이 문서는 그 README 에 없는 파일별 판단만 적는다. 세션 쪽은
[hyprland.md](hyprland.md#화면-셰이더), 거는 스크립트는 [rice-scripts.md](rice-scripts.md).

## crt/crt.frag

브라운관 룩. 렌더링이 끝난 화면 한 장을 받아 마지막에 한 번 더 그리므로 바탕·바·창·커서가 전부 같은 유리 뒤로 들어간다.

**한 장인 이유.** 정지판과 움직이는 판(crt-motion)을 두 파일로 두면 같이 고쳐야 할 코드가 어긋난다(대조 결과: curve·
gun·focusAt·bloom·stripes·bezel 의 주석 뺀 코드 차이 0 줄인데 FOCUS 0.18 vs 0.32, FOCUS_NEAR 0.25 vs 0.28 로 갈라져
있었다). 지금 값은 0.18/0.25 다. 정지판을 얻으려면 GRAIN 0, HUM·HUM_LIFT·HUM_GLOW 0, RIPPLE_GAIN/LIFT/GLOW 0.

**흐르는 것을 꺼 두면 값을 안 치르게 하는 장치 둘:**

1. 유니폼 분기(맥 판 기준) — 손잡이로 승격된 값은 유니폼이라 컴파일러가 못 접는다. main() 에서 `if (GRAIN > 0.0)` 로
   감싸면 유니폼 하나로 갈리는 분기라 워프가 통째로 같은 쪽으로 가서 실제로 안 돈다. 안 감싸면 상시 비용이다(12.1ms →
   14.0ms). 리눅스에서는 `#define` 이 상수라 컴파일러가 접어 비용 0 이다.
2. `!motion` — 재그리기 판정을 `time` 유무로만 하면 GRAIN=0 이어도 늘 켬이 되어 "정지 화면 비용 0" 이 사라진다. 판정은
   `apps/rice/chain --motion` 이 `!motion` 손잡이로 한다(README 「손잡이가 시간을 여닫는다」).

Mod+Shift+C 가 off → crt.frag 을 오간다. 흐르는 것을 끄고 켜는 것은 셰이더 교체가 아니라 손잡이 일이다.

**뿌리.** `modules/shared/ghostty/shaders/crt.glsl`([ghostty 셰이더](ghostty-shaders.md))을 옮겼다. 터미널 창 하나용이라
화면 전체에선 과해서 손잡이마다 낮췄다. 그 셰이더의 뿌리는 space_dots(Golden Era) 라이스의 Maxim Samoliuk Hyprland 화면
셰이더(MIT)이고, 블룸·그레인·깜빡임·색수차·가장자리는 다시 짰다. 출처는 `modules/nixos/hyprland/rice/SHADER-CREDITS.md`.
저장 즉시 반영된다.

**포인터 유니폼.** 문서에 없는 유니폼으로 0.56 의 renderToOutputInternal()(src/render/OpenGL.cpp)이 넘긴다. 전부
damage_tracking = 0 을 요구하지만 어차피 꺼야 해서 추가 비용이 없다(조사 기록 `_temp/ricing/`). 좌표는 0..1, 모니터
로컬, 곡률을 먹기 전 텍스처 좌표계다 — 커서도 화면과 같이 휘어 텍스처에 이미 그려져 있으므로 curve() 를 통과한 uv 와
그대로 비교한다.

**클릭 이력.** index 0 이 최근이고 새 클릭마다 앞으로 밀린다(OpenGL.cpp 의 addLastPressToHistory). times 는 클릭 이후
실제 초라 ANIM_SPEED 와 무관하다. 크기 32(macros.hpp 의 POINTER_PRESSED_HISTORY_LENGTH). 상류 버그:
`shader->setUniform2fv(SHADER_POINTER_PRESSED_POSITIONS, pressedPos.size(), ...)` 가 vec2 개수(32)가 아니라 float
개수(64)를 넘겨 glUniform2fv 가 128 float 를 읽으려 든다(0.56.1 과 main 둘 다). 넘치는 원소는 무시되므로(OpenGL ES 3.0:
"values for all array elements beyond the end of the array will be ignored") [32] 선언이 맞다. debug:gl_debugging =
true 로 GL 에러 없음을 확인했다.

**링 리플.** 반지름만 자라고 두께는 유지한다(두께까지 키우면 커지는 원반이 되어 화면 절반이 밝아지는 순간이 생긴다).
pow(x,2.0) 대신 곱하기를 쓰는 건 밑이 링 안쪽에서 음수이기 때문이다(험 바도 같은 이유).

**험 바·리플이 블룸을 세게 미는 이유.** 띠가 지날 때 밝은 것 둘레가 확 번지는 게 브라운관에서 실제로 눈에 띄는 부분이고,
리플도 누른 자리의 번짐이 링보다 먼저 눈에 들어온다. 이 곱하기 때문에 체인으로 쪼갤 수 없다(뒷칸은 합성된 색만 보고
블룸 항을 못 만진다).

**명암 순서.** 더하기 전부 뒤(들어 올린 검정을 도로 누르는 게 목적), 비네트(bezel) 앞(가장자리 죽이기는 이미 곱하기).
max() 는 그레인이 검정 근처를 음수로 밀 때 pow(음수, 소수) = NaN 을 막는다.

## water/still.frag (물 셋의 기준)

셋이 공유하는 결정(왜 굴절인지, 가장자리와 글자 처리, 못 고치는 것)은 still 에만 적는다. 값과 함수를 나눠 쓸 방법이
없어 복제다(화면 셰이더는 전처리를 안 거쳐 #include 가 없다).

**왜 굴절인가.** 파란 색을 얹는 것은 물이 아니다. 물로 보이는 것은 물 너머가 밀려 보이는 것이고, 그러려면 자기 픽셀
밖을 읽어야 한다(맥 README 표에서 캡처 방식이 아니면 안 되는 쪽 — 감마 LUT·블렌드 오버레이는 `tex` 를 못 읽어 색조만
남는다). 알맹이는 두 줄: 높이 h 의 기울기를 구하고 그만큼 uv 를 밀어 읽는다. 색과 반짝임은 장식이다.

**잔물결은 노이즈가 아니라 사인 넷.** 잔잔한 물의 결은 몇 개의 긴 파가 겹친 간섭무늬라 노이즈면 자글거린다. 사인이면
기울기를 해석적으로 내서 표본을 더 뜨지 않고 차분 계단도 없다. 파수 벡터는 서로 정수배가 아니어야 한다(정수배면 격자로
되풀이돼 벽지가 된다). 마주 보는 두 파가 어른거리는 무늬를 만든다.

**대가.**
1. 재그리기: `time` 을 읽어 정지 화면에서도 주사율대로 그린다. 물에는 선택지가 없다 — 노트북 배터리가 주는 곳.
2. 커서 어긋남(맥): 커서는 윈도서버가 오버레이 위에 그려 셰이더를 안 먹으므로, 커서가 가리키는 픽셀이 실제로는 REFRACT
   픽셀만큼 밀려 있다. 셰이더 쪽에서 못 고쳐 REFRACT 기본값이 1.6 px 로 작고, 큰 값은 상시용이 아닌 ocean 에 있다.

**가장자리.** 샘플러가 clampToEdge(맥 Sources/Renderer.swift)라, 밀린 uv 가 화면 밖이면 테두리 한 줄이 늘어나 네 변에
띠가 생긴다. EDGE_FADE 폭에 걸쳐 밀림만 0 으로 접는다. 색·반짝임은 밖을 안 읽으므로 안 접는다(접으면 테두리만 물이
아니게 된다).

**클릭 링 기울기.** 단면 exp(-e²) 의 미분 -2e·exp(-e²). 1/CLICK_W 를 안 곱하는 건 CLICK_W 를 줄일 때 기울기가 폭발해
CLICK 이 뜻을 잃기 때문이다(필요한 건 모양).

**busy().** 글자가 많은 자리에서 물을 줄이는 판정이다. 최대가 아니라 평균 — 최대면 대비 큰 모서리 하나에도 1 이 되어
창 테두리·바탕화면 무늬에서까지 물이 꺼진다. 나선 탭은 crt bloom() 과 같은 이유(링은 방향 수만큼 결이 남는다).
PRESERVE 0 이면 탭을 안 뜬다(유니폼 분기).

**물비늘.** 기울기를 법선으로 세워 빛과 맞댄다. 평평한 물에서도 내적 0.89 의 24 제곱 ≈ 0.06 이 남아 옅은 윤기가 된다.

**알파.** 맥은 오버레이 레이어가 불투명이라 버려지고, 하이프랜드도 결과가 그대로 프레임버퍼로 가므로 1.

## water/river.frag

강을 강으로 만드는 것은 높이를 만드는 방식 셋이다.

- **방향**: 사인을 밀면 무늬가 통째로 미끄러져 스크롤하는 벽지가 되므로 FBM(여러 옥타브 노이즈의 합)을 쓴다. 밀어도
  무늬가 계속 새로 생긴다.
- **늘어남**: STRETCH 가 노이즈 좌표를 흐름 축으로만 눌러 이방성을 만든다(없으면 "흐르는 안개").
- **휨**: WARP 가 낮은 주파수 결을 따라 좌표를 밀어(도메인 워프) 소용돌이·굽이를 만든다(FBM 두 번 값; 없으면 빗질 자국).
  굽이는 낮은 주파수 결의 등고선을 따라(기울기를 90도 돌려) 민다 — 기울기 방향이면 결이 뭉개진다.

**기울기는 해석적.** 유한차분이면 FBM 을 세 번 잰다. noised() 는 삼차 보간 u = f²(3-2f) 의 도함수 du = 6f(1-f) 를
그대로 써 값과 기울기를 한 번에 낸다(굴절은 기울기를 직접 써서 차분 계단이 화면에 보인다). 픽셀당 비용은 FBM 두 번 =
노이즈 여덟 번 = 해시 32 번, 전부 ALU 라 crt 의 픽셀당 20여 회 텍스처 페치보다 쌀 것으로 보지만 재지 않았다.

**옥타브.** 기울기에도 주파수를 곱해야 연쇄법칙이 맞다(안 곱하면 결이 있는데 안 밀리는 물). 배율 2.03: 정확히 2 배면
옥타브 격자가 같은 자리에 겹쳐 격자 무늬가 비친다.

좌표 변환을 행렬 대신 내적 둘로 쓴 이유: mat2 의 열 우선 규약에서 부호를 틀리기 쉽다. 회전은 직교변환이라 역이 전치다.
워프의 야코비안은 굴절에 필요 없어 생략한다.

## water/ocean.frag

셋 중 유일하게 상시용이 아니다. REFRACT 기본값 7 px 에서 커서 어긋남이 명백하고 너울마다 움직이며, 글자도 PRESERVE 를
끝까지 올려야 겨우 읽힌다. 결함이 아니라 성격이다 — 잔잔한 수면은 걸어 두고 일하는 것, 바다는 보는 것. 그래서 still
과 합쳐 손잡이만 달리 두지 않았다.

- 너울은 사인 셋(기울기 해석적, 대체로 같은 쪽으로 — 흩어지면 물이 끓는 것처럼 보인다), 잔물결만 FBM(사인으로 쌓으면
  되풀이가 보인다). 사인 파의 기울기는 마루에서 최대·골에서 0 이라 굴절 밀림이 마루를 저절로 뾰족하게 만든다 —
  게르스트너 파의 수평 밀림이 REFRACT 를 키우면 저절로 나온다.
- 잔물결 기울기에는 촘촘함이 곱해져 있어(연쇄법칙) 그대로 더하면 CHOP 을 올릴 때 잔결이 너울을 덮는다. 촘촘함으로 나눠
  CHOP 이 "세기" 뜻을 지킨다.
- 깊이: 화면 위가 수면, 아래가 깊은 곳. 아래로 갈수록 짙어지고 붉은 쪽이 먼저 빠진다(파장이 긴 빛이 먼저 흡수). 억지
  원근이지만 화면 아래는 대개 독·창 아랫부분이라 잃는 정보가 적고 위쪽 메뉴 막대는 밝게 남는다.
- 옥타브 셋: 넷째는 굴절 폭보다 잔결이 작아 안 보이고 값만 낸다. 마루의 거품은 잔물결을 한 번 곱해 부서진 자국이 된다.

## cyberpunk/glitch.frag

대부분의 시간에 아무 일도 안 일어나야 한다. 계속 지직거리면 3초면 질리고 30초면 못 쓴다. 그래서 시간을 칸으로 잘라
칸마다 주사위를 던진다:

- `tick = floor(time * RATE)` — 칸 번호
- `hash(tick) > 1 - DENSITY` — 이 칸에 터지나
- `fract(time * RATE)` — 칸 안 경과 → 감쇠

DENSITY 0.12 면 여덟 칸에 한 번쯤이다. 사인·노이즈로 흔드는 방식과 달리 아무 일도 없는 구간이 진짜 0 이다(step()
이라서; smoothstep 이면 "거의 안 터진 칸"이 늘 약하게 걸린다).

밀림은 clamp 가 아니라 wrap(fract())이다. 어긋난 띠가 반대편에서 이어져 나오는 것이 프레임버퍼가 어긋나 읽힐 때의
실제 모습이고, 접으면 양끝에서만 어긋남이 사라져 가짜로 보인다. 띠 번호에 tick 을 섞어야 칸마다 다른 띠가 걸린다.

체인 마지막 칸용이다(앞칸 결과를 신호로 보고 망가뜨림). 예: neon → glitch, paper → glitch(인쇄물이 깨진다). `time` 을
읽으므로 이 칸이 들어가면 체인 전체가 재그리기 켬이 된다.

## cyberpunk/neon.frag

crt bloom() 과 탭 모양은 같지만 고르는 기준이 다르다. 브라운관은 인광체가 밝게 탄 자리가 번져 휘도가 맞지만, 네온은
흰 창·흰 글씨가 아니라 어두운 바탕 위의 짙은 색(프롬프트 색, 문법 강조색, 아이콘 원색)이 탄다(crt 의 BLOOM_CUT 0.22 가
화면 전체를 들어 올리는 것과 다른 축).

- 채도폭은 HSV S(=(mx-mn)/mx)가 아니라 mx-mn 이다. S 면 거의 검정 (0.02,0,0) 도 1 이라 배경 잡티가 전부 간판이 된다.
  폭은 "얼마나 짙은가"를 그대로 내고, 어두운 쪽은 LUMA_FLOOR 전에 이 값이 먼저 거른다.
- 나선 탭 수는 반경이 넓어 crt 의 16 보다 촘촘하다.
- 체인 뒤칸용: crt → neon(브라운관 네온), neon → glitch(간판이 튄다). 깜빡임을 안 넣은 이유: `time` 을 읽으면 재그리기가
  켜지고, 겹쳐 쓰는 파일은 그 값을 혼자 정할 수 없다(crt 뒤에 걸면 "정지 화면 공짜"가 날아간다).

## print/paper.frag

전자잉크 룩. 읽으려고 만든 룩이라 모든 결정이 가독성으로 기운다(잔글씨를 뭉개면 실패). print 갈래의 다른 후보(리소
망점, 게임보이 4색)는 본문이 안 읽히는 대신 룩을 얻는 쪽이라 남기지 않았다.

- **SHARP**: 다른 셰이더가 흐리는 쪽인데 여기만 날을 세운다. 탈색과 명암 압축이 획을 흐려 보이게 해서, 되돌리지 않으면
  빛바랜 화면이 된다. 언샵 마스크는 탈색 전에 건다.
- **그냥 흑백이 아닌 이유 셋**: 흰색이 안 하얗다(종이 흰 곳 0.93 쯤, 살짝 따뜻함; 순백이면 발광으로 보임), 검정이 안
  검다(잉크 0.12 쯤; 0 이면 OLED), 결이 있다(종이 섬유 얼룩; 시간이 안 들어가 화면 자리마다 고정 — 창을 옮겨도 결은 그
